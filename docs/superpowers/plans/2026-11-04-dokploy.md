# Dokploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Preparar un único Compose para Dokploy con PostgreSQL y DNS internos estables.

**Architecture:** Una entrada HTTP (Nginx frontend), API por Gateway y Socket.IO por Messaging. PostgreSQL privado con tres bases; Admin conserva su acceso a Identity.

**Tech Stack:** Docker Compose, PostgreSQL 17, Nginx, Node/Drizzle/pg, Spring Boot/Flyway.

**Spec:** `docs/superpowers/specs/2026-11-04-dokploy-design.md`

## Global Constraints

- No publicar puertos de servicios internos ni PostgreSQL.
- Mantener usuarios y bases separados para Identity, Catalog y Messaging.
- No incorporar secretos reales ni migrar datos existentes.
- Mantener los nombres internos `cecar-*` del diseño.

## Review Focus

- PostgreSQL no debe declararse listo durante su servidor temporal de inicialización.
- Admin no debe arrancar antes de las migraciones de Identity.
- Reiniciar debe aplicar solo migraciones pendientes.
- HTTP y WebSocket deben compartir origen y conservar cookies.
- El contexto Docker no debe copiar `.env` ni dependencias locales a las imágenes.
